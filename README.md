# Агент-триаж научных статей под тему диплома

## Проблема

Когда пишешь диплом, скачиваешь десятки PDF-статей и тратишь время, разбираясь, какие
релевантны теме. Прогонять каждую целиком через LLM — дорого и долго. Этот агент делает
**триаж**: ранжирует статьи по близости к теме (дёшево, кодом) и зовёт LLM **только** для
вердикта по топ-кандидатам — «подходит / спорно / не подходит», с объяснением и ссылкой на страницу.

## Как устроен pipeline

```
papers/*.pdf + thesis.md
  1. extract  PyMuPDF -> текст + номера страниц            (код)
  2. chunk    нарезка с overlap                             (код)
  3. embed    dense (Gemini) [+ sparse BM25 при HYBRID]     (API + код, кэш на диск)
  4. index    точки в Qdrant on-disk                        (код)
  5. plan     LLM строит под-запросы/термины из thesis.md   (LLM)   ← агентность #1
  6. triage   близость статья↔тема, агрегируем по статье    (код)   ← дёшево, без LLM
  7. judge    цикл "хватает ли доказательств?" по топ-K ->  (LLM)   ← агентность #2
              [нет -> дозапрос] -> вердикт -> самопроверка          ← агентность #3
  8. output   report.md + trace.json + run.log
```

**Где LLM, а где обычный код:**
- *Код:* чтение PDF, чанкинг, дедуп (sha256), эмбеддинги, гибридный поиск, scoring, пороги, отчёт.
- *LLM:* планирование поиска, решение «достаточно ли контекста», вердикт с обоснованием,
  самопроверка обоснования против цитат (анти-галлюцинация), честный отказ.

## Запуск

**Через меню (рекомендуется):** двойной клик по `run.bat` (Windows) или:
```bash
python -m src.menu
```
Пункты: статус • список файлов индекса • запуск (доиндексация при необходимости) •
принудительный пересбор • dry-run • открыть отчёт/лог • гибрид • быстрый режим • тесты.

**Напрямую через CLI:**
```bash
python -m venv .venv && .venv\Scripts\activate      # Windows (или source .venv/bin/activate)
pip install -r requirements.txt
cp .env.example .env                                 # вписать ключи (опционально)
python -m src.cli --dry-run                          # без ключей: только триаж кодом
python -m src.cli                                    # полный режим (если ключи в .env)
python -m src.cli --check-index                      # показать, что проиндексировано
```

**Индексация инкрементальная:** в `qdrant_db` хранится манифест с хэшем каждой статьи.
При запуске индексируются только новые/изменённые PDF, уже готовые не пересчитываются,
удалённые из папки вычищаются. Полный пересбор — только при смене конфига (hybrid/режим
эмбеддингов/чанкинг) или флагом `--rebuild`.

- **`JINA_API_KEY`** — эмбеддинги `jina-embeddings-v3` (как в оригинале) ([jina.ai/embeddings](https://jina.ai/embeddings)).
- **`OPENROUTER_API_KEY`** — LLM-вердикты ([openrouter.ai/keys](https://openrouter.ai/keys)).
- Без ключей всё работает в **dry-run**: триаж по детерминированным hashed-эмбеддингам, вердикты
  по относительной близости, LLM-промпты пишутся в `trace.json` как «что бы сделал агент».
- `HYBRID=true` в `.env` включает sparse BM25 + dense с RRF-слиянием (как в оригинале).

## Пример входа

`papers/smith2021_fraud_lstm.txt` (статья про LSTM-автоэнкодеры для детекции мошенничества) +
`thesis.md` (тема: детекция аномалий во временных рядах банковских транзакций).

## Пример результата (`output/report.md`)

| Статья | Вердикт | Близость | Почему |
|---|---|---|---|
| smith2021_fraud_lstm.txt | ✅ подходит | 1.0 | LSTM-автоэнкодеры для fraud в транзакциях, метрики F1/AUPRC, поток *(стр.1)* |
| jones2019_sensor_ts.txt | 🟡 спорно | 1.0 | anomaly detection во временных рядах, но домен — промышленные сенсоры, не финансы |
| lee2020_image_segmentation.txt | ❌ не подходит | 0.5 | про сегментацию изображений, не по теме |

Плюс `output/run.log` (хронология) и `output/trace.json` (шаги, score, итерации агента, тайминги).

## Надёжность (обрабатываемые случаи)

- пустая папка `papers/` → понятное сообщение, без падения;
- скан/пустой PDF (нет текстового слоя) → пропуск с пометкой;
- дубли статей → дедуп по sha256, индексируем один раз;
- слишком длинная статья → лимит чанков (`MAX_CHUNKS_PER_PAPER`);
- нет API-ключа → авто dry-run;
- ошибка LLM/сети → retry с backoff, затем деградация до триажа;
- **rate limit (429)** → throttle между вызовами (`LLM_MIN_INTERVAL`) + экспоненциальный backoff
  с уважением `Retry-After` (`LLM_MAX_RETRIES`); число вызовов можно ужать флагами
  `AGENT_LOOP`/`SELF_VERIFY` (минимум — 1 plan + 1 verdict на статью);
- нерелевантная статья → «не подходит» без траты LLM.


## Стек

Python · PyMuPDF · Qdrant (on-disk, embedded) · Jina `jina-embeddings-v3` (как в оригинале) ·
fastembed BM25 · OpenRouter (OpenAI-совместимый) · requests · python-dotenv.
Без Docker, без GPU, без LangChain.

## Limitations и Next steps

См. одноимённые секции в `output/report.md`. Кратко: только текстовый слой PDF (нет OCR);
dry-run-вердикты эвристические; корпус рассчитан на 5–10 статей. Дальше: разбивка вердикта по
исследовательским вопросам, гибрид по умолчанию + reranker, OCR для сканов.
